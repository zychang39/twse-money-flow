# 第四輪：底部導覽與個股頁左右換股（2026-09-27）

兩項介面調整，依「問題 → 根本原因 → 設計決策 → 實作 → 驗收」記錄。截圖在 [`round4/`](round4/)（iPhone 393pt，真實資料，深淺色）。

## 1. 底部導覽：搜尋併入分頁列、選取膠囊滑動、Instagram 式玻璃質感

**需求**：搜尋包進底部的分頁列，放在右手拇指最順手的第 4 格；切換時比照 Instagram，選取狀態滑過去；顏色、透明度與效果照 Instagram 的截圖調整。

**原本的問題**
- 搜尋是分頁列右邊獨立的圓形按鈕（第一輪的 iOS 26 做法），不在拇指最常停的位置，視覺上也是兩個物件。
- 選取狀態只是圖示變藍，切換時沒有位置上的連續性；而且換頁時整頁（含導覽列）都在做 View Transition，導覽列會跟著頁面滑動。
- 導覽列背景偏不透明、沒有邊框與高光，和截圖裡的玻璃膠囊差距大。

**設計決策**
- **5 格**：今晚、我的股票、探索、**搜尋（第 4 格）**、紀律。和 Instagram 一樣，搜尋在右手拇指自然落點。
- **選取膠囊**：目前分頁底下一顆較亮的膠囊（深色 14% 白、淺色 7% 黑），切換時以 Web Animations 從舊位置滑到新位置，中途橫向拉長、縱向略扁再回彈（液態玻璃感）；減少動態效果時直接跳到新位置。
- **按住拖曳**：手指在導覽列上左右拖曳時，膠囊放大 12%、加一點陰影並跟著手指，放開即切到手指下方的分頁（iOS 26／Instagram 的操作）。
- **玻璃質感**（深淺色各一組 tokens，`--tab-*`）：半透明底（72%）＋ blur 28px／saturate 180%；0.5px 細框、上緣 1px 高光、兩層柔和陰影；圖示一律白色（淺色為近黑），選取的圖示描邊加粗（1.8 → 2.2）。不再用藍色標示選取：位置與膠囊已經足夠，藍色保留給一般的可互動元素。
- **切換分頁不做整頁轉場**：內容直接替換，只有膠囊在動（Instagram 的做法）；同一分頁內的推入／返回仍有轉場，但導覽列有自己的 `view-transition-name`，不再跟著頁面滑動。
- **搜尋頁**：導覽列保留（搜尋分頁為選取狀態），搜尋框在導覽列正上方；鍵盤開啟時導覽列淡出、搜尋框貼在鍵盤上方（第一輪的鍵盤行為不變）。在搜尋頁再點一次搜尋分頁會回到搜尋框。

**踩到的坑**：`view-transition-name` 一開始放在外層 `.dock`，導覽列的背景模糊就失效了——有 view-transition-name 的元素是 backdrop root，模糊只能取到它裡面的內容。改放在導覽列本身。

**實作**：`web/src/lib/tabs.ts`（分頁定義、`isTabSwitch`）、`components/Chrome.tsx`（Dock）、`router.ts`（分頁切換不轉場、`navigate(…, 'none')`）、`styles/tokens.css`（`--tab-*`）、`styles/global.css`、`pages/Search.tsx`。

**驗收**：`e2e/round4.spec.ts` 第 1 組（順序、膠囊位置、動畫與減少動態效果、拖曳切換、鍵盤開啟淡出、玻璃樣式）；`ux-fixes.spec.ts`、`smoke.spec.ts` 已改成 5 格。截圖 `*-01～05`（`02-dock-sliding-*` 是動畫中的三個畫格）。

> 註：雲端截圖環境的無頭 Chromium 不會畫出這個版面的背景模糊（第一輪的截圖也一樣），導覽列底下的文字看起來是清楚的；真機 Safari 會模糊。

## 2. 個股頁左右換股：上下不動、中間像 Apple 股市一樣帶出前後一檔

**需求**：在上半部左右滑動換股時，上下畫面不動；中間的主角區參考 Apple 股市，往左右拖動時後一檔或前一檔一起被帶出；不要黑屏或卡頓。

**根本原因**
1. 原本是整頁（含頂列與下方全部內容）跟著手指位移 40%、同時淡出，放開後才換網址。
2. 換網址時觸發整頁 View Transition；新的一檔在轉場開始時還沒有資料，截到的新畫面是載入骨架（深色背景下看起來像黑屏）。
3. 相鄰股票沒有預先載入；資料 hook 每次換股都會先回到「載入中」。

**設計決策**
- **只有主角區在動**：名稱、股價、走勢圖（含期間選擇）是一條「前一檔｜目前｜後一檔」的軌道，1:1 跟著手指；頂列（清單名稱、n / N、星號、進階）與下方所有內容不動。
- **放開後吸附**：拖曳超過寬度 28% 或放開時速度 > 0.45 px/ms 就換到相鄰一檔（380ms、ease-out），否則彈回；第一檔往右、最後一檔往左是橡皮筋阻尼。
- **吸附完成才換網址**，而且不做整頁轉場、不捲回頂端；軌道在同一個畫面內重新置中，內容不變所以看不出跳動。下方內容換成新的一檔並淡入。
- **不等待資料**：相鄰兩檔（與再下一檔）預先載入；新的 `useStockData` 會同步取用已載入的資料，換股時不會先變成載入中。
- **和查價不衝突**：走勢圖在可換股的區域改為**按住約 0.2 秒**才開始查價（之後可以任意拖曳，頁面也不會捲動）；快速左右滑動交給換股。滑鼠仍是移動即查價。
- **無障礙**：非目前的一檔 `inert`＋`aria-hidden`；頂列的 ‹ › 走同一個動畫；減少動態效果時直接換。
- **效能**：第一次開啟先畫目前這一檔，閒置後才畫相鄰兩檔；下方內容只在換股後淡入（第一次淡入會延後 LCP，實測個股頁效能 81 → 93）。

**實作**：`components/StockPager.tsx`、`pages/Stock.tsx`（`StockHero`）、`components/HeroChart.tsx`（`holdToScrub`）、`hooks.ts`（`useStockData`）、`data/api.ts`（`peekStock`）。

**驗收**：`e2e/round4.spec.ts` 第 2 組（以 DevTools Protocol 送出真正的觸控事件）：三格軌道與 inert、拖曳中後一檔進入畫面且頂列與下方內容位置不變、換股過程沒有載入畫面、橡皮筋與距離不足彈回、‹ › 動畫、按住查價不換股；`interactions.spec.ts` 的滑鼠拖曳換股仍通過。截圖 `*-06～08`（`07-stock-swiping` 為拖曳中）。
