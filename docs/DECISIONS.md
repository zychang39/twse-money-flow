6. **data 分支結構**：孤兒分支 `data` 根目錄為 `raw/{來源}/{YYYY}/{YYYYMMDD}.csv.gz` 與 `manifest.json`；Actions 將它 checkout 到工作目錄的 `data/`，因此本機路徑為 `data/raw/…`。月資料（月營收）以該月 1 日為檔名；年資料（休市日曆、美債）以 1 月 1 日為檔名；區間查詢的資料（除權息、注意、處置）依事件日期切檔。
7. **Python 3.12 + pandas 3**：衍生計算涉及全市場約 2,000 檔 × 3 年日資料，採 pandas/numpy。版本以 `==` 鎖定。
8. **TypeScript 6.0.3**：typescript-eslint 8.70 的 peer 範圍為 `<6.1.0`，因此不採用 TS 7。
9. **法人成本線**：只納入視窗內淨買超日（Σ淨買超 × 均價 ÷ Σ淨買超），避免淨買賣相抵時分母趨近 0 造成數值爆炸；UI 註明為估算值。
10. **分數映射**：採分段線性、事前設定的透明參數（見 `config/scores.yml`），不做資料最佳化；缺資料的因子不計入並標示。
11. **現金股利**：上市除權息結果只有「權值＋息值」合計。「息」事件直接視為現金股利；「權息」事件若有預告表的現金股利就用預告值，否則以合計值近似並在 UI 標示（多數公司近年僅配息，影響有限）。

25. **央行 M1B／M2**：採用央行開放資料 `EF15M01.csv`（貨幣總計數日平均、月資料；data.gov.tw dataset 6024，政府資料開放授權第 1 版），每週六檢查一次，整份 CSV 以最新月份存成快照；市場燈號取最新一期 M1B 與 M2 年增率比較。
26. **法說會**：公開資訊觀測站「法人說明會一覽表」（ajax_t100sb02_1，GET）每週抓本月與下月（上市＋上櫃），只供行事曆使用，不進入分數。
27. **AI 摘要**：只在 deploy 時且有 `ANTHROPIC_API_KEY` 才產生當日盤後條列摘要；模型不寫死，預設用 Models API 回傳的最新模型（可用 `ANTHROPIC_MODEL` 覆寫）；只餵已產生的衍生數據，提示詞禁止交易建議字眼，輸出再以關鍵字過濾，前端標示「AI 生成」。以 HTTP 直接呼叫，不新增 SDK 相依。
28. **分點券商資料：不實作**。證交所「買賣日報表查詢系統」（bsr.twse.com.tw）與櫃買「券商買賣證券日報表」查詢都必須輸入驗證碼，官方 OpenAPI 與開放資料平臺沒有分點進出資料；其餘第三方網站需登入或授權不明。依「只使用合法、免費、不需驗證碼的來源」規則不實作，若日後官方提供開放資料再評估。
29. **完整回補為預設**：`backfill` 未指定來源時補齊所有可回補的來源（registry.BACKFILL_FULL）；借券、外資持股、當沖等進階每日資料只補近 400 天，以控制請求量（約 8,000 次請求、分 2–3 輪自動串接）。月份型來源完成後記錄在 manifest 的 `backfilled`，續跑時略過；近兩個月可能仍有更新，不標記完成。集保股權分散表官方只提供最新一週，無法回補。
30. **M3 還原價實測（真實資料）**：以 Actions 回補的 data 分支（2025-03-27～2026-09-24 共 368 個交易日、除權息／減資 2020-09 起）執行 `build-web`（約 6.5 分鐘、summary gzip 224 KB），抽查還原因子在每個事件日的跳動換算回的參考價，全部等於官方參考價：台積電 6 次除息（例：2026-09-16 前收 2,385、息 7 元 → 2,377.99）、鴻海 2 次、聯發科 3 次、0050 3 次除息。0050 在 2025-06-18 的 1 拆 4 分割：該批回補尚未包含 TWTCAU 分割表，由價格跳空推估補上，因子 0.249987（188.65 → 參考價 47.16 = 188.65 ÷ 4），還原價無斷層；第 2 批回補會補入官方分割紀錄，屆時以官方事件為準、推估事件自動讓位。

## 2026-09-27 設計改版（B「環境光」）
31. **美術方向**：使用者選定 B「環境光」並修正語意：今晚頁光暈只代表資金環境燈號（保守＝琥珀，其餘＝極淡灰藍，不用紅綠）；我的股票與個股頁光暈＝主角數字所選期間的漲跌，與走勢線共用同一個期間計算（`sliceWindow`），切換期間時光暈（透明度交叉淡入）與走勢線（spring 變形）同步；其他頁面不使用光暈。光暈為靜態 `radial-gradient`，不做即時模糊；設定可關閉（即 A「夜間簡報」），`prefers-reduced-transparency`／`prefers-reduced-motion` 時以 CSS 自動隱藏。
32. **資金環境燈號的顏色**：色彩預算規定紅綠只代表漲跌，因此 5 項資金指標彙總為「積極／中性／保守」三態（任一風險＝保守；無風險且 ≥ 3 項有利＝積極），只有保守用琥珀；單項指標以實心（有利）、灰（中性）、琥珀（風險）、空心（資料累積中）圓點表示。門檻在 `config/ui.yml`。
33. **介面行為參數集中在 `config/ui.yml`**：顯著變化門檻、燈號彙總、冷靜卡條件、回測可信度、XP 與徽章。只影響呈現，不影響分數與指標計算；方法說明頁自動列出。預設門檻經真實資料檢視後調整（法人占量 25%、連買 5 日、融資 8%），避免首次查看時大多數自選都被列為「顯著」。
34. **「上次查看」**：每個範圍（今晚、我的股票）在本次開啟 App 時讀取上次的快照當基準，並把目前資料寫成下次的基準；同一次使用期間基準固定，來回切頁不會把變化「看掉」。第一次使用時以前一交易日為基準（summary 的日變化欄位）。主角數字另外記錄上次查看的值，用來做數字滾動與「較上次查看」淡色標籤。
35. **期間選擇器**：以日曆期間取基準點（區間開始前最後一個交易日收盤，與漲跌計算一致）；YTD 以前一年最後一個交易日為基準；只有日資料，1D 為「昨收 → 今收」兩點；資料不足所選期間時在圖下說明。個股走勢用還原價（最新一日＝實際收盤）。
36. **持股組合的主角數字**：以「目前持有股數 × 還原收盤價」計算走勢，最新一日等於實際市值、除權息不造成斷層；等所有持股的歷史都載入後才計算，避免把不完整的值記成「上次查看」。完整的權益曲線（含已平倉、股利）仍在紀律 → 個人統計。
37. **清單 sparkline**：近 20 個交易日還原價，虛線＝昨收，顏色＝今日漲跌（與右側漲跌膠囊一致），避免「線是紅的、膠囊是綠的」這類矛盾。
38. **遊戲化只獎勵紀律**：活動紀錄存在 IndexedDB `activity`（DB v2，納入備份；舊備份匯入時自動補空陣列）。XP 只來自看完簡報、完成檢查表（含「檢查後決定不進場」，避免獎勵變成鼓勵下單）、平倉檢討、備份、回測自己的條件，並設每日上限；連續天數只計交易日（index.json 的交易日），休市日不中斷；徽章指標沒有交易次數與損益。「守住停損」＝虧損出場、出場價落在停損價的 −4%～＋2% 之間，且未標記「未守停損」。可在設定關閉遊戲化（改為純文字待辦，紀錄仍保存）。
39. **第二環「新持倉都完成檢查表」**：新增持倉本來就必須完成檢查表，因此沒有新持倉時視為完成並顯示「今天沒有新持倉」；它的主要作用是讓「檢查後決定不進場」也能被記錄與獎勵。
40. **冷靜卡**：新增持倉時若資金環境為保守、收盤高於 20 日均線超過 10%、或近 5 日漲幅超過 15%，先列出事實，需勾選「我已看過以上事實」才能繼續；語氣中性、不說教，也提供「先不要」。
41. **動畫的例外**：元素移動一律用 transform／opacity；只有 SVG 走勢線的「由左到右描繪」（stroke-dashoffset）與期間切換的路徑變形（以 requestAnimationFrame 直接改 `d`，重新取樣成 160 點內插）是小型 SVG 的重繪，不觸發版面計算。頁面轉場用 View Transitions API（不支援則直接切換）。減少動態效果時全部停用。
42. **字體**：數字與英文用 `@fontsource-variable/inter`（精確版本）自託管，只打包拉丁子集並預載，`unicode-range` 限制只接管拉丁字元；中文仍用系統字體。全站 `tabular-nums`。
43. **驗收截圖用真實資料**：所有截圖、走查與前後對照都用 data 分支 600 個交易日的真實衍生資料；使用者資料（自選、持倉、日誌）是測試輸入，價格取自真實收盤（`web/scripts/make-seed.py`）。截圖以 JPEG（q=82）存放以控制 repo 大小。CI 的 Playwright 仍用示範資料（不需要 data 分支）。
44. **狀態設計**：休市與「今天的資料尚未更新」改為資料日期列的內嵌提示（平靜、不造成版面位移）；只有資料過期用琥珀提示卡；空狀態一律附下一步按鈕；「資料累積中」（集保大戶等）以專用提示說明起始與原因；錯誤狀態提供重試與資料健康連結。

## 2026-09-27 行動體驗修正（詳見 docs/design/UX_FIXES.md）
45. **底部導覽一列化**：搜尋從「漂浮在 Tab 上方的膠囊」改為 Tab 膠囊右側的圓形按鈕（iOS 26 慣例），兩層合併成一列；往下捲動時縮小（56 → 44px），往上捲、停止捲動 700ms 或換頁時恢復。精簡型態仍保留 4 個 Tab 可點（不像 iOS 只留目前的 Tab），因為本 App 的 Tab 切換頻率高、手機單手操作時不希望多一步展開。

47. **搜尋改為獨立頁面 `#/search`**：可用返回鍵離開、可分享網址；搜尋頁隱藏底部導覽，改為底部搜尋列＋「取消」。畫面以 visualViewport 的可見區域定位（top＝offsetTop、height＝vv.height），鍵盤開啟時輸入框貼在鍵盤正上方，也一併抵銷 iOS Safari 開鍵盤時把版面往上推的位移；搜尋期間鎖住頁面捲動。iOS 只在使用者手勢內聚焦輸入框才會叫出鍵盤，因此點搜尋按鈕時先同步聚焦一個隱形輸入框，搜尋頁掛載後再把焦點移過去（鍵盤保持開啟）。這些行為無法在 Chromium 自動化測試，列入 README 的真機手動驗收清單。
48. **搜尋結果由下往上**：DOM 順序仍是「最相關在前」（螢幕閱讀器與鍵盤順序正確），以 `flex-direction: column-reverse` 讓最相關的顯示在最靠近輸入框的位置；鍵盤 ↑ 從輸入框移到最相關的結果。排序：代號完全相同 > 名稱完全相同 > 代號開頭 > 名稱開頭 > 名稱包含 > 名稱依序包含每個字，同分依成交值（`web/src/lib/search.ts`，加入自選面板也共用）。空白時顯示最近搜尋（最多 8 筆，存在 IndexedDB 設定）、自選股、熱門動能前 5 名，所有來源到齊才一次畫出，避免區塊先後出現造成版面位移（Lighthouse CLS 0.20 → 0）。結果列不用 listbox／option（列內有「加入自選」按鈕，listbox 不能包含其他互動元素），改為清單＋按鈕。
49. **焦點框改畫在內側**：`.input`、搜尋框、搜尋結果列的焦點框改為 `box-shadow: inset`，任何 `overflow: hidden`／捲動容器都不會裁切上緣（原本外框被面板的捲動容器切掉）。
50. **「自選｜持股」且自選預設**：`#/mine` 預設自選，持股為 `#/mine?seg=hold`；舊網址 `?seg=watch` 仍有效。持股組合的主角走勢只在持股分段顯示（自選分段的環境光為中性）。頁首結論以全部自選（不受群組篩選影響）為準，有持股時再加上持股狀況。
51. **系統清單「熱門動能」**：由 pipeline 在部署時依 `config/ui.yml` 的規則產生 `lists.json`（成交值排名前 150 名、RS 百分位 ≥ 80、沒有危險級旗標且注意級最多 1 個、依 RS 取前 10 檔、不含 ETF），規則寫在 METHODOLOGY 第 9 節。為什麼在 pipeline 而不是前端算：規則是單一事實來源、可測試，也讓 Telegram 等伺服器端功能日後可以共用。App 內一律標示「依規則產生，非推薦」、唯讀；「複製成我的群組」會建立「熱門動能 M/D」群組（已在自選的維持原群組，並告知檔數）。
52. **歡迎卡與範例自選**：只在「還沒有任何自選」時出現在我的股票的自選分段；範例清單在 `config/ui.yml`（台積電、鴻海、聯發科、廣達、0050），加入時標示來源為範例、放在「範例」群組，並在清單上方顯示「清除範例」；清除只刪 `origin = 'sample'` 的項目；使用者自己加入的不受影響，範例股被移到其他群組時視為使用者決定留下，來源改為 user，清除時也保留。
53. **IndexedDB v3 遷移**：自選新增 `origin`（user／sample／hot）與索引。升級在 versionchange 交易內逐筆補 `origin: 'user'`，其他欄位與其他 store 原樣保留；備份檔 v2 → v3 也補同樣的欄位。以 fake-indexeddb 單元測試與 Playwright（先在同源建立 v2 資料庫再開 App）驗證既有資料不遺失。
54. **今晚頁主角數字**：主角數字下方固定顯示「今日」漲跌（最新收盤對前一交易日；拖曳時為該日對前一日）；走勢圖期間預設 3M、選項從 1W 開始（只有盤後日資料，1D 只是兩點直線）、期間只改變走勢圖，區間漲跌標在圖表上方。今晚頁的期間選擇不記憶（每晚都從 3M 開始，符合盤後簡報的脈絡）；我的股票與個股頁維持原本的期間語意與記憶。
55. **中文排版**：標題與結論句用 `text-wrap: balance`（不支援時 `pretty`）＋`word-break: keep-all`＋`line-break: strict`，只在標點與空白處換行；結論句數字前後用不換行空白，所以實際上只會在「，」後換行。結論改寫成每個子句 ≤ 12 個全形字寬、整句最多兩行（例：「自選 8 檔，其中 2 檔有顯著變化。」），有單元測試檢查寬度、Playwright 在 393 寬實測行數。
56. **欄位相容策略（資料源）**：見 METHODOLOGY 第 1 節。根本原因是上櫃本益比回補 2024 年以前的日期時，回應沒有「財報年/季」欄位（2025 年起才有），原本的解析器要求所有欄位都在，導致回補連續失敗 180 次、資料健康頁與每頁頁首都顯示異常。改為「必要／選用欄位＋別名」後兩種格式都能解析，舊格式記錄格式變動警告。以位置解析的表格（欄名重複）無法安全地容忍欄位插入或刪除，仍整批失敗，由冒煙測試提早發現。
57. **資料源異常的顯示範圍**：manifest 的失敗分成「影響最新資料」（每日型落後、從未成功，或非每日型失敗）與「只影響回補的歷史日期」。頁首「N 個資料源異常」只看前者，而且只看該頁實際用到的來源（`web/src/lib/health.ts` 的 `PAGE_SOURCES`），改為琥珀色小字；資料健康頁以白話說明為主，技術訊息與格式變動警告收在「詳細資訊」。
58. **修改 smoke-test.yml**：CLAUDE.md 規定使用者建立的 `smoke-test.yml` 不要修改；這次使用者明確要求擴充冒煙測試，因此只「新增」一個 `fields` job（呼叫 `python -m pipeline smoke`），原本的 `probe` job 一字未改。
59. **每日籌碼改用三種檢視**：12 個欄位在 375pt 寬度下不可能同時放下，因此以分段控制切換「法人｜信用｜借券當沖」（預設法人），每種 4 欄；收盤與漲跌 % 不佔欄位，以小字放在日期下方。橫向或平板寬度放得下時同時顯示 12 欄（分組標題），字級放大放不下時改為卡片（2×2）。版面由實際量到的文字寬度（canvas measureText，與儲存格同字型；數字換成 0 以符合等寬數字）決定，不用固定斷點，才能同時涵蓋 375／393、Dynamic Type 與不同語系字型。
60. **信用與借券當沖檢視的欄位**：個股檔新增借券餘額（`sblb`）與當沖量（`dtv`），以股保存。區間合計列：數量欄加總、餘額欄為區間增減（帶 ▲▼）、比率欄為區間平均（當沖比率以成交量加權、券資比＝Σ融券餘額 ÷ Σ融資餘額）。餘額換算成「佔成交量」沒有意義，因此選該單位時餘額仍以張顯示並在標題下方註明；比率欄不隨單位變動、數值帶 %。
61. **11pt 次要小字**：數字維持 13pt（caption），日期下方的收盤／漲跌與標題下方的連買天數用 11pt（HIG caption2，token `--fs-micro`）。13pt 時「2,475 ▼1.00%」需要約 92px，日期欄會變成約 100pt，4 個資料欄在 375 寬放不下連買天數；11pt 時日期欄約 89pt（規格的「約 72pt」在 13pt 下做不到）。這是 5 級字級之外唯一的例外，只用在密集表格的次要資訊。
62. **比例條畫在數字下方**：規格是「很淡的橫向比例條」。實測整格底色會和數字重疊，看起來像雜亂色塊，也會降低文字對比；改為貼在格子底部的 3px 細條，從中線向左右延伸（長度＝|值| ÷ 該欄所選期間的最大 |值|），另有極淡的中線刻度。
63. **整列可點、透明按鈕蓋住日期格**：VoiceOver 需要唸完整句子（「9 月 24 日，外資賣超 485 張…」），但如果按鈕內有可見的「9/24」，無障礙名稱就和可見文字不一致（WCAG 2.5.3，Lighthouse `label-content-name-mismatch`）。因此可見的日期與收盤是 aria-hidden 文字，按鈕是蓋住整格的透明元素，名稱就是完整句子；整列的點擊也開啟同一個面板。
64. **每日籌碼預設展開、延後渲染**：預設展開後表格在首次載入時渲染，個股頁 Lighthouse 效能掉到 87。明細在個股頁畫面之外，因此區塊接近畫面（600px 內）或瀏覽器閒置時才渲染明細（先顯示同高的骨架，不造成版面位移）；同時把 `toLocaleString` 改為共用的 `Intl.NumberFormat`（全站 `fmtNum` 一併受益）、量字改用 canvas。個股頁回到 90–95。
65. **「估成交量」**：程式中的字一直是「佔」（U+4F54）；小字級時「佔」與「估」只差右上一筆，雲端截圖環境唯一的中文字型（文泉驛正黑）兩者幾乎相同，因此截圖看起來像錯字。依要求把選項改為「佔成交量 %」，加上字元層級的單元測試與頁面檢查，截圖改用 Noto Sans TC（只在截圖腳本注入，不打包）。台灣教育部的標準字是「占」，若日後仍有混淆可改用「占成交量」。
66. **「⋯」選單與單位下拉**：單位用原生 `<select>` 疊在自訂外觀的按鈕上（iOS 會跳出系統選單、鍵盤與輔助科技都可用）；「⋯」是 HIG 的 pull-down menu（role=menu，Esc 與點外面關閉），目前只有「複製為 CSV」一項，把不常用的動作從主畫面移開。

## 2026-09-27 第三輪修正（詳見 docs/design/ROUND3.md）
67. **每日籌碼仍是收合的根本原因**：HIG 改版的 commit 是在 PR #6 合併之後才推送，沒有進入 main，因此正式站仍是舊版（舊版預設收合）；已在新分支帶上。另外 App 外殼是 cache-first，加入主畫面的 App 可能一直停在舊版：改為回到前景時呼叫 `registration.update()`，新版本接手（controllerchange）後顯示「新版本已就緒」，由使用者按「重新載入」，不在操作途中自動重新整理。第一次安裝（原本沒有 controller）不提示。
68. **法人買賣超報表的資訊架構**：上方「區間合計」一次列出外資、投信、自營商、三大法人（概覽，點一列即切換）；Tab 切換下方單一法人的走勢圖與逐日明細（細節）。手機直向放不下「4 個法人 × 買張／賣張／買賣超」12 欄，逐日明細只列目前法人的買張、賣張、買賣超、累計；「⋯ → 複製為 CSV」一次輸出四個法人的全部欄位。窄螢幕或字級放大時，渲染後量測是否有儲存格被裁切，才拿掉「累計」（明細）或「佔量」（合計）欄，不用固定斷點。期間 1／2／3 個月＝20／40／60 個交易日，預設 3 個月。
69. **八大行庫**：需要券商分點進出資料，官方查詢頁有驗證碼（本環境對證交所頁面直接被安全機制擋下），依規則不實作；分頁保留，標示「資料源待處理」，說明原因、資料接上後會列出的欄位（買賣超、庫存、持股比率），並列出可自行查詢的官方頁（需驗證碼）與第三方彙整網站（標示非官方、不擷取；第三方的「庫存」是累計推估）。
70. **法人買進／賣出股數與 `backfill --refresh`**：官方一直有買進、賣出股數，但較早只保存了外資與投信的買賣股數。解析器新增外資自營商與自營商（自行買賣／避險）的買賣股數（選用欄位）；舊檔以 `--refresh` 重抓補齊。refresh 只在指定來源時有效（避免誤觸整批重抓），驗證失敗仍保留原檔，且不自動接續下一輪（下一輪會從最近日期重抓、無法前進）。順帶修正回補接續時讀取不存在的 `next_start` 造成的 KeyError。
71. **共用日期軸的小倍數圖（StackedChart）**：股價與買賣超單位不同，不做雙軸；改成上下對齊同一組日期的多個面板，各自一個 y 軸（收盤價、買張與賣張、每日買賣超、累計買賣超）。刻度取 1、2、2.5、5 × 10ⁿ，柱狀圖以 0 為中線上下對稱；多條線以實線／虛線＋標題列右側的圖例區分（不靠顏色，線尾標籤在密集資料上會和線重疊，已改為圖例）；十字線＋提示框，可用方向鍵逐日查看並以 aria-live 讀出數值；整張圖是 role=img，逐日數值另有表格。
72. **券商研究報告不擷取**：賣方報告多為付費或只提供客戶，沒有官方來源；新聞轉述的目標價是媒體著作。只提供標示「第三方」的連結（Google 新聞搜尋、鉅亨網、Yahoo 股市），另以官方法說會公告整理「主辦／邀請券商」（文字擷取，擷取不到顯示「公司自辦」）。
73. **集保個股歷史只回補關注清單**：開放資料只有最新一週；集保官網可逐檔查一年但頁面註明多檔需求請用開放資料，因此只對關注清單（指定代號＋範例自選＋成交值前 30 名，最多 60 檔）回補一次，不排入排程；每次最多 1,500 次查詢、可續跑。之後每週的新資料一律由開放資料取得；同一週兩邊都有時以開放資料為準。
74. **大戶／散戶門檻只能停在集保分級邊界**：分級內各持有人的張數未知，任意門檻（例：300 張）只能內插、會失真，因此滑桿只停在 14 個邊界。散戶＝「X 張以下」、大戶＝「超過 Y 張」，兩者之間為中實戶；雙滑桿用兩個原生 range 疊在同一條軌道上（鍵盤、VoiceOver 都能調整，圓鈕 28px，觸控區 44pt），兩者不會交叉；上次的門檻記在 IndexedDB。常用組合：千張大戶、400 張大戶、百張大戶、散戶放寬到 50 張。
75. **多空對照只做條件統計**：22 項規則式條件，每項只屬於多方、空方、中性或資料不足之一，權重相同、不加總成分數；中性與資料不足也列出目前數值，避免只看得到觸發的條件。用「多方／空方」與「偏多的依據／需要留意的依據」，不用買賣字眼；同一件事可能同時出現在兩邊（例：營收成長但本益比偏高），在規則說明中寫明。
76. **工具頁放在個股的子路由**：`#/stock/:code/institutional`、`/holders`、`/bullbear`，入口放在個股頁相關區塊內（法人、籌碼、多空），可直接分享網址；工具頁的 CSS（tools.css）隨頁面分塊載入，不增加首頁與個股頁的大小（首次載入 JS 仍為 43 KB gzip）。

## 2026-09-27 第四輪：底部導覽與個股頁左右換股（詳見 docs/design/ROUND4.md）
77. **搜尋併入分頁列、放在第 4 格**：取代第一輪「分頁膠囊＋右側圓形搜尋」的做法。5 格依序為今晚、我的股票、探索、搜尋、紀律；搜尋在右手拇指最順手的位置（與 Instagram 相同）。取代 DECISIONS 第 45 條的搜尋按鈕位置，其餘（bottom: 0、safe-area、往下捲縮小）不變。
78. **選取狀態改為滑動膠囊、不用藍色**：切換時膠囊以 Web Animations 滑過去（中途拉長再回彈）；手指按住導覽列拖曳時膠囊放大並跟著手指、放開即切換。圖示統一用文字色（深色白、淺色近黑），選取的描邊加粗。藍色只保留給一般的可互動元素，選取狀態由位置與膠囊表達。

## 可用性測試修正（第 2 輪，2026-09-29）

129. **#1 Service Worker 更新**：根本原因有三：(a) 新版 SW 在 install 時就 `skipWaiting`，頁面的 `controllerchange` 監聽卻在 `load` 之後才接上，啟動時很快完成的更新會錯過，沒有任何提示；(b) install 用 `addAll` 取外殼，`index.html` 會經過瀏覽器 HTTP 快取與 GitHub Pages CDN（`max-age=600`），部署後 10 分鐘內安裝的新版 SW 可能把**舊的** `index.html` 永久存進新快取，使用者重新整理也一直是舊版；(c) `caches.match` 依快取建立順序查找，舊快取裡的 `index.html` 會先被找到。修法：外殼一律 `cache: 'reload'`，`index.html` 另加 `?v=版本` 避開 CDN，並確認它引用這一版的入口 JS，不符就讓安裝失敗（下次再試，不留半套快取）；fetch 先查這一版的快取；新版安裝後停在 waiting，由 `lib/swUpdate` 決定：啟動或回到前景 3 秒內、沒有點擊或按鍵、沒有開啟面板（`role=dialog`）或聚焦輸入框 → 自動 `SKIP_WAITING` 並在 `controllerchange` 重新載入；否則只顯示「有新版本，點此更新」（不遮擋、不打斷表單）。設定頁「檢查更新」、設定頁與資料健康頁顯示版本「commit 短碼・建置日期（台北）」（Vite `define`）。註冊改用 `updateViaCache: 'none'`，監聽不再等 `load`。activate 保留前一版外殼一份（其他分頁可能仍在跑舊版，懶載入的舊檔案還拿得到）。從舊版 SW（沒有 SKIP_WAITING 協定）升級時，新版沿用舊行為直接接手一次，舊頁面照舊顯示提示。
130. **#2 距 52 週高點**：查證結果**不是還原價的問題**。pipeline 的 `dist_52w_high` 一直是 `close × af` 的 rolling max（`metrics.py`），前端直接顯示這個值。用 data 分支重跑 build-web，逐一比對近 52 週內有分割、減資、推估面額變更或大額配息（因子 < 0.8）的 66 檔：pipeline 的值全部等於用還原價計算的結果，和原始價算法差距很大（如 0052 分割：原始價 −74.96%、還原價 −0.08%；6949 分割：−96.62% 對 −32.48%）。使用者看到的案例是 2492 華新科（311.5、240 日線 215.3、RS 95）：6/22 收 617（還原 613.73）後連續跌停，7/17 已到 307.5，期間只有 7/9 一次 0.99 的除息，所以 −49.3% 是真實跌幅；240 日線低是因為一年中大半時間股價在 100 附近。為了讓這類數字可以自己核對，個股頁「距 52 週高點」下方加上「高點 613.73（2026/6/22，還原價）」；前端另有同定義的 `high52w`（pipeline 沒有值時使用，例如最後一日無成交），pytest 與 vitest 共用 1:4 分割的 golden 檔。
131. **#3 「今日」漲跌**：根本原因是 HeroChart 用「視窗內相鄰兩點」算今日漲跌，而 10Y、ALL 的視窗是週線取樣（M5），相鄰兩點相隔一週。`Window` 新增選用的 `daily`（同一價格基準的完整日資料），個股頁一律附上個股檔的日收盤（`heroSeries.withDaily`；10Y／ALL 的視窗來自長歷史檔也一樣）；`periods.windowDayChange` 以日期在日資料中找前一個交易日比較，查價到週線上的某一點時也顯示「該日」相對前一交易日的漲跌。今晚頁與我的股票的視窗本來就是日資料，行為不變。
132. **#4／#5 個股頁 `.sx-*`、`.cr-*` 樣式**：根本原因是這些規則寫在 `styles/tools.css`，而這份 CSS 只由工具頁（法人報表、大戶持股、多空對照）與 Structure 元件 import；個股頁的 `StockSections.tsx`（動能、營收、獲利區塊）與 `Credit.tsx`（信用卡片、外資持股比）沒有 import。Vite 依分塊拆 CSS，所以直接開啟個股頁時樣式不存在，只有先進過工具頁、或捲到 Structure 區塊載入後才出現（不是 purge 或 class 名稱問題）。修法：兩個元件自己 import `tools.css`（Vite 去重，不增加首頁 CSS），檔頭註明規則；e2e 讀 `dist/.vite/manifest.json`（build 開啟 manifest，SW 外殼排除 `.vite/`），確認這兩個分塊自己帶到含 `.sx-facts`、`.cr-row` 的 CSS。外資持股比改為同一行「69.20%　▲0.35 百分點」（`credit.foreignHoldLine`）；沒有 20 個交易日前的持股比時顯示「變化：資料累積中」並在基準文字註明「8/27 無資料」，不再用持平樣式的「—」。
133. **#6 每日籌碼表的單位**：根本原因是格式以「欄」為單位決定（`colFormat`：該欄最大值 ≥ 1 萬就整欄萬張 1 位小數），所以同一張表外資、合計是萬張、投信、自營商是張，表格上方仍寫「單位：張」，萬張欄的小量四捨五入成 ▲0.0。改為以「表」為單位（`chips.tableFormats`／`viewFormats`：法人、信用、借券當沖各是一張表）：張數最大 < 1 萬 → 整張表千分位整數；≥ 1 萬 → 整張表萬張 1 位小數，未滿 1,000 張的格子寫整數張「▲315張」（「張」為小字，量欄寬時分開量，375pt 仍排得下表格），表格上方單位改為實際單位「萬張（未滿千張寫張）」（`tableUnitLabel`），不再在欄名後面黏「萬張」。億元、佔量 % 也改為整張表同一種小數位；非 0 但四捨五入為 0 時寫「<0.01」。只寫張數（完全不用萬張）的做法試過：60 日的區間合計（如 −210,345）讓 375pt 的欄寬不夠，會退回每日卡片版面，所以採用上述做法。另修正 e2e 共用的 `revealAllSections`：佔位元素在捲動途中被移除時 `scrollIntoViewIfNeeded` 沒有逾時，會一直等到整個測試逾時（main 上 chips.spec 有 3–4 個測試因此不穩定）。
134. **#7 動能結論**：原本 `momentumTone` 只有 RS ≥ 70 且站上**全部**均線才算「偏強」，RS 88、多頭排列但跌破 20 日線就落到「中性」，和同頁「跌破 20 日線」讀起來矛盾。改為長期強度（RS＋年線／排列）與短期位置（20／60 日線）分開判斷，一致時合成一句、不一致時分開寫（規則見 METHODOLOGY §4.14）。
