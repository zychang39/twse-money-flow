# v3 優化紀錄（資深投資人 × 資深工程師）

每項格式：**問題 → 根本原因 → 決策 → 驗收**。「投資人」判斷資訊對「波段動能」與「長期投資」的決策價值與呈現方式；「工程師」負責根本原因、資料與效能方案、測試。

## M0：背景回補

### M0-1 自營商與三大法人的買張／賣張大多是「—」
- 問題：法人買賣超報表的自營商、三大法人合計，買張與賣張在 2026-09 以前幾乎都是「—」。
- 根本原因：解析器 2026-09 才開始保存自營商（自行買賣／避險）的買進與賣出股數，較早的每日檔只有買賣超（見 `pipeline/sources/twse.py`）。已存在的檔案不會被一般回補重抓。
- 決策：用既有的 `backfill --refresh` 重抓近 3 個月的 `twse_insti,tpex_insti`（不需改程式）。回補完成前，報表在「—」旁加註「資料回補中」；買賣超（官方合計數）不受影響，仍照常計算。
- 驗收：2026-09-28 以 workflow_dispatch 在 main 觸發 Data workflow：`task=backfill, source=twse_insti,tpex_insti, start=2026-06-26, end=2026-09-26, refresh=true`（API 回 204，已排入佇列）。完成後報表的「*」與「資料回補中」註記會自動消失（`buySellSince` 往前移）。

### M0-2 大戶與散戶走勢只有 1 週
- 問題：集保股權分散表開放資料每週只給最新一週，趨勢需要逐週累積。
- 根本原因：資料源限制；個股歷史查詢（`tdcc_history`）只在明確指定時執行。
- 決策：觸發 `task=backfill, source=tdcc_history`（只針對關注清單、約 1.5 小時、可中斷續跑；同一個 concurrency group 會排在 M0-1 之後）。
- 驗收：同日觸發（204，已排入佇列）。前端在資料不足時改為單點標記＋「資料累積中」說明（見 M1-1）。

## M1：錯誤修正與快速改善

### M1-1 線圖只有座標軸、標題寫「走勢・1 週」
- 問題：個股頁「大戶與散戶走勢」只有座標軸；選「6 個月」時標題寫「走勢・1 週」。
- 根本原因：①正式站的集保資料只累積了 1 週（開放資料每週只給最新一週，個股歷史尚未回補）；②`StackedChart` 逐點以 `M/L` 串路徑，只有 1 點時路徑只有一個 `M`，畫不出任何東西，週增減柱的第一週又必為空值 → 只剩座標軸；③標題用 `series.dates.length`（可用週數）而不是所選期間。其他圖表也有同類問題：`LineChart` 少於 2 點直接顯示「資料不足」、`sliceWindow` 只有 1 個交易日回傳 null（主角圖空白）、`Sparkline` 少於 2 點畫空 svg；缺漏造成的孤立點在所有折線圖都會消失。
- 決策（投資人）：資料少不是錯，要讓人知道「目前有多少、從哪天起、之後會補」，而不是空白。（工程師）新增純函式 `lib/series.ts`：`segments()` 把序列切成線段與孤立點，孤立點畫成單點標記；`coverage()／coverageNote()` 產生「資料累積中：目前只有 N 週（自 M/D 起），所選期間超過可用資料；歷史回補中」。`StackedChart`、`LineChart`、`HeroChart`、`Sparkline` 全部改用；標題改寫所選期間。
- 驗收：`series.test.ts`（線段／孤立點／全缺值／頭尾孤立點、coverage 文字、單點視窗、單值座標軸、只有 1 週的集保序列與結論句）；Playwright `v3-m1.spec.ts`：截成 1 週的集保資料選 6 個月 → 標題「走勢・6 個月」＋說明＋每個折線面板都有單點標記；截成 1 個交易日的股價 → 主角圖有單點與說明。

### M1-2 返回時捲動位置與狀態遺失
- 問題：從清單點進個股，再按左上角返回或左緣右滑，清單回到頂端，排序、群組、展開都重設。
- 根本原因：①路由每次 hashchange 都 `scrollTo(0, 0)`；②左上角返回是 `<a href="#/mine">`（新增一筆紀錄，不是返回）；③瀏覽器的自動還原在資料非同步載入時，還原時頁面高度不夠會被夾到頂端；④分段控制、篩選是元件內的 useState，卸載即消失。
- 決策（工程師）：`history.scrollRestoration = 'manual'`；每筆紀錄在 `history.state` 補 key 與 App 內序號，scrollY 與元件狀態以「路由＋key」存 sessionStorage（`lib/scrollRestore.ts`）；離開前一次寫入所有仍在畫面上的狀態（`useRestoredState` 註冊）；返回時等頁面高度足夠再捲回（ResizeObserver＋rAF，4 秒上限，使用者先動手即放棄）。左上角返回在 App 內改用 `history.back()`，直接開啟的網址才前往預設上一層。個股之間換股是 `location.replace`，清單那一筆紀錄不受影響。套用到我的股票（群組、排序、展開）、產業、選股、搜尋、今晚、市場溫度、行事曆、法人報表（分頁、期間）。
- 驗收：Playwright：12 檔自選、排序改「漲跌幅」、捲到中段 → 點進個股 → 左上角返回：位置誤差 ≤ 8px、排序保留；同上但先換股再用瀏覽器返回：同樣 ≤ 8px；直接開啟個股網址 → 返回到清單。

### M1-3 移除八大行庫
- 問題：「八大行庫」分頁只有「資料源待處理」佔位畫面。
- 根本原因：資料只有付費來源（免費分點查詢頁需驗證碼）。
- 決策（投資人）：決策價值有限（主要反映大盤急跌時的護盤，且混有一般客戶委託），轉載付費資料有條款風險 → 不採用，移除分頁、佔位畫面、說明與外部連結；分段控制只留外資、投信、自營商、三大法人。DECISIONS #84、DATA_SOURCES「不採用」。
- 驗收：Playwright：法人分段控制只有 4 個按鈕，頁面與個股頁都沒有「八大行庫」字樣。

### M1-4 深淺色
- 問題：跟隨系統，白天打開是淺色；切換藏在設定頁深處；重新整理會先閃一下淺色。
- 根本原因：主題存在 IndexedDB（非同步），`applyAppearance()` 要等 App 掛載後才套用。
- 決策：預設深色、不跟隨系統；三段式（深色／淺色／跟隨系統）放在頭像選單第一列；存 localStorage 單一鍵 `tmf-theme`，`<head>` inline script 在第一次繪製前套用並同步 `theme-color`（DECISIONS #85）。
- 驗收：`theme.test.ts`（預設值、解析、inline script 在 meta 之後）；Playwright：系統為淺色時仍是深色、兩個 theme-color 都是 #000000；選單第一列三段式；切淺色後 localStorage 與 theme-color 更新；重新整理時 DOMContentLoaded 前已有 `data-theme`。

### M1-5 個股頁期間
- 問題：1D 只有兩點直線；主角數字下方只有所選期間漲跌，看不到今天。
- 決策（投資人）：波段看 1Y、當天看今日，兩者都要一眼看到 → 移除 1D、預設 1Y；主角數字下方兩行「今日漲跌」「所選期間漲跌」（DECISIONS #87）。
- 驗收：Playwright：期間沒有 1D、1Y 預設選中；兩行文字隨期間改變。

## M2：籌碼資訊重新整理

### M2-1 每日籌碼表（Apple HIG）
- 問題：每格數字下方的比例條與靠右對齊的數字對不齊；同一欄有的寫「1.2 萬」、有的寫「8,765」，小數點對不齊；列太擠。
- 根本原因：比例條以欄中線為原點向左右延伸（有正負），數字卻靠右；格式是逐格決定（`compactNum` 每格自己判斷要不要縮寫成萬）。
- 決策（投資人）：表格是拿來「比大小、看連續」的，一欄一種格式最重要；趨勢感改由表格上方的三大法人柱狀圖提供。（工程師）`colFormat()` 以整欄（含區間合計）最大絕對值決定：≥ 10,000 張 → 整欄萬張 1 位小數（標題標「萬張」），否則千分位整數；億元／佔量依最大值決定 2／1／0 位；`cellText()` 拆出箭頭與數字，箭頭縮小、底部對齊；列高 52pt（`--row-table`）、日期 15pt、日期下方 12pt、分隔線 inset；區間合計列底色、連續天數維持在標題下方。量測欄寬的隱藏元素改用相同字級（否則「▼1.34%」會被裁掉）。
- 驗收：`chips.test.ts` 手算（[−485, 20,000, 12] → 萬張：▲2.0、▼1.2、▼0.0；[−9,999, 1,234] → 整數；0 →「0」）；Playwright：沒有 `.cd-bar`、有柱狀圖、每欄小數位數一致、靠右＋等寬數字、箭頭字級小於數字、列高 50–56px、日期 15px／小字 12px、合計列底色不同；375／393pt 三種檢視 × 三種單位 × 期間都不需要左右滑動。

### M2-2 拆開「信用與籌碼」
- 問題：融資、融券、外資持股、千張大戶混在同一個清單，也沒寫「跟什麼時候比」。
- 根本原因：區塊是依資料來源（融資融券表）堆出來的，不是依決策問題。
- 決策（投資人）：波段最常問「散戶在追價還是退場？空方有沒有回補壓力？」→ 拆成「散戶信用（融資）」與「空方（融券與借券）」兩張卡；外資持股屬於法人動向，移到法人區塊；千張大戶移到籌碼結構。每個數字都寫「與 N 個交易日前（M/D）相比」。價量解讀四種標籤（價漲資增／價漲資減／價跌資增／價跌資減）各附一句中性說明（METHODOLOGY §4.7.5）。券資比 ≥ 30% 說明軋空風險。（工程師）純函式 `lib/credit.ts`（`deltaOver`、`priceMarginLabel`、`creditSummary`），價格用還原價；融資使用率用 summary 的 `margin_usage`，取不到時寫原因。「借券餘額」改名「借券賣出餘額」（資料其實是 TWT93U 借券賣出餘額）。
- 驗收：`credit.test.ts` 手算（融資 1,000 → 1,100＝▲100 張（+10.0%），基準 9/17；還原價 +4%＋融資 +10% → 價漲資增；券資比 330 ÷ 1,100＝30.0% → 偏高；四種標籤、持平不套用、說明句不含買賣字眼）；Playwright：兩張卡、比較基準文字、外資持股在法人區塊、券資比 35% 時出現軋空說明。

### M2-3 大戶與散戶（籌碼結構）
- 問題：圖表寫「大戶（超過 100 張）」，其他地方是 400 或 1,000 張；定義不一致。
- 根本原因：大戶門檻可調（預設 400、常用組合有百張大戶，且設定會被記住），同一個詞在不同畫面代表不同分級。
- 決策（投資人）：可調門檻對決策是雜訊，統一成散戶 ≤ 5 張／中實戶／大戶 ≥ 400 張／千張大戶 ≥ 1,000 張，寫在 `config/ui.yml holders.tiers` 並顯示在畫面上；個股頁新增「籌碼結構」區塊：一句話結論（「千張大戶本週 +0.19 個百分點，連 3 週增加」）、四段堆疊比例條與每段週變化、「查看趨勢」底部面板（比例／人數／人均張數）；15 級完整分布頁保留。（工程師）`tierOf／tierWeek／tierStats／structureSentence`；比例條四段互斥（大戶段 400–1,000 張）。
- 驗收：`holders.test.ts` 手算（分級對應、第 3 週四段比例 20／31／10／39 加總 100、散戶人數 31,800、千張人均 39,000 張、千張 37→38→39 連 2 週 +1.00、只有 1 週與持平的句子）；Playwright：定義句、沒有滑桿、沒有「超過 100 張」、四段比例條、底部面板指標切換。

## M3：個股頁依投資風格重新排序

### M3-1 一種順序服務不了兩種決策
- 問題：個股頁區塊順序固定（法人 → 籌碼 → 多空 → 營收 → 研究 → 估值），波段交易者要往下找動能，長期投資者要越過一大段籌碼才看到營收與獲利。
- 根本原因：區塊依「資料來源」排列，不是依「決策問題」；區塊標題只寫「法人」「籌碼」，要讀完內容才知道結論。
- 決策（投資人）：新增設定「投資風格：波段動能／長期投資」（預設波段）。波段：動能 → 法人 → 信用與空方 → 籌碼結構 → 營收 → 估值 → 事件；長期：營收成長 → 獲利品質 → 估值（本益比河流）→ 籌碼結構（含外資持股比趨勢）→ 法人 → 信用 → 事件。每個標題寫成「問題＋一句結論」（「動能夠不夠強？RS 14，跌破 20／240 日線」）。多空對照降級併入「整體狀態」、研究參考併入「事件」。一句話結論依風格：波段看動能、法人連續、融資價量；長期看營收、ROE、本益比位置。（工程師）`lib/style.ts`（SECTION_ORDER、預設期間）、`lib/fundamentals.ts`（均線排列、營收新高與連續成長、EPS／ROE、本益比河流）、`lib/verdict.ts`（依風格的結論）；個股頁改為 `sections[id]()` 依順序渲染；pipeline 的季表新增單季 EPS 與近四季 ROE；新增 5Y 期間，兩種風格的期間分開記住。
- 驗收：`verdict.test.ts` 手算（3 日均線、上漲序列 → 多頭排列與「RS 87，站上全部均線」、下跌序列、只站上 60 日線的例子、連續年增 10 個月、近四季 EPS 9.50 vs 5.50、毛利率 +2.0 個百分點、兩種風格的結論句、百分位內插 18／30、河流中線 24.5 倍 × EPS 5 元）；`test_financials.py`（單季 EPS 0.5、ROE 20%）；Playwright `v3-m3.spec.ts`：兩種風格的區塊順序與預設期間、長期投資有本益比河流與外資持股比趨勢、切換風格即時重排且各自記住期間。

## M4：兩指區間報酬

### M4-1 看不到「某段期間」的報酬
- 問題：走勢圖只能查單點，想知道「從上次突破到現在漲了多少」要自己心算。
- 根本原因：HeroChart 只有單一指標（scrub）狀態，沒有區間的概念；觸控只追蹤一個 pointer。
- 決策（投資人）：波段檢討進出點、長期看持有報酬都需要區間報酬，而且要含股利 → 預設還原價，可切換原始價。（工程師）`lib/rangeReturn.ts`（純函式：排序兩端、漲跌、報酬率、交易日數）；HeroChart 以 Map 記錄每一指的位置，第二指落下進入區間模式（取消按住查價、捕捉兩個 pointer、`stopPropagation` 讓外層換股不接手、`touchmove` 取消捲動），手指移動即時更新；放開保留 2 秒再淡出（減少動態效果時直接消失）；桌機按住拖曳。
- 驗收：`rangeReturn.test.ts` 手算（100 → 110＝+10、+10.00%、3 個交易日、手指順序無關、夾到邊界、除息時還原價 0% vs 原始價 −4%）；Playwright `v3-m4.spec.ts`（CDP 多點觸控）：兩條標線與日期／交易日數／報酬率、移動時更新且交易日數變大、主角數字不變、放開 1 秒仍在、約 2 秒後消失；單指仍是查價；清單中兩指左右移動不會換股；桌機拖曳、切換原始價並記住。

## M5：10 年歷史股價

### M5-1 只有 3 年股價，長期投資看不到完整循環
- 問題：收盤行情只回補 3 年，長期投資者看不到一個完整景氣循環（5–10 年），也沒有 5Y／10Y 期間。
- 根本原因：backfill 未指定起日時一律 3 年；而且所有衍生計算（指標、分數、回測）與個股檔都用「全部」收盤行情，直接回補 10 年會讓每個寬表變成約 2,450 × 2,500 格、個股檔變大 3 倍以上。
- 決策（投資人）：股價要 10 年；籌碼類（法人、信用、借券、集保）3 年已足夠判斷，不回補 10 年。（工程師）
  - backfill：只指定收盤行情（`twse_quotes,tpex_quotes`）且未給起日時預設 10 年，其他來源維持 3 年（`config/sources.yml history`）；各來源有「最早可取得日期」，早於此日不發請求；沿用既有的禮貌爬取（3–5 秒＋抖動）、已存在略過、時間預算用完自動接續（可中斷續跑）。
  - 衍生計算視窗：build-web 只用最近 1,100 個交易日（約 4.5 年，涵蓋 3 年百分位與 240 日線）計算指標、分數、回測與個股檔，計算量與個股檔大小不隨歷史長度成長。

## 收尾

### 效能
- 問題：個股頁區塊變多（8 個區塊、信用、籌碼結構、本益比河流），Lighthouse 行動版個股頁一度 80–89（同一環境的 main 為 87）。
- 根本原因：個股頁的 JS 包含所有區塊元件；第一次繪製就畫出全部區塊（Chips、Structure 的計算與版面量測集中在同一個長任務）；LCP 元素（「整體狀態」的一句話結論）要等整個 Stock chunk 下載、解析。
- 決策（工程師）：區塊標題（問題＋一句結論）留在個股頁 chunk，細節元件（Chips、Credit、Structure、StockSections、Research、StockExtras）改為 `lazyPick` 延後載入；只先畫前兩個區塊，其餘在哨兵接近畫面時一次補一個（IntersectionObserver，返回還原捲動位置時直接全部畫出）；8 個期間按鈕平均分配整列寬度。
- 驗收（本環境，示範資料，Lighthouse 12 行動版模擬節流；本環境比 REVIEW.md 當時慢，main 同環境為今晚 93、個股 87）：今晚 98、我的股票 98、個股 91–93（中位數 92，最差一次 84，雜訊大）；無障礙 100、最佳做法 100。首次載入 JS（index＋預載 chunk）約 51 KB gzip，進入個股頁再加約 25 KB（< 250 KB）。WCAG AA 對比：`scripts/contrast.py` 深淺色全部 ≥ 4.5:1。
